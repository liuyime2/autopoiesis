## 2. 项目实际在做什么

建议当前对外定位：**可审计、带硬风控和策略生命周期的 LLM paper-trading 研究系统**。

长期使命仍是能自主改进并持续盈利的交易 agent。当前价值已经体现在：运行交易闭环、保留证据、发现错误测量、撤回不成立的结论。持续盈利、LLM 增益、自我演化提升表现都还需要进一步验证。

执行链路：`cli → daemon → loop → guardian → executor → journal`。规则先决定，LLM 可带理由改判；Guardian 审核后才提交 Alpaca paper 订单。维护链路完成成交核对、FIFO 账本、反事实评分、反思、提议策略、准入和晋升/暂停/退役。research 与 production 的导入边界已有验证机制。

近期提交集中在标的资料、账户交易范围、风险判断、研究比较、模型实验、命名迁移和网络故障恢复。未提交工作正在把 VIX 用作波动率预测下限，并增加质量判断窗口；不能将它写成已发布功能。

| 能力 | 当前判断 | 下一步所需证据 |
|---|---|---|
| paper 数据、决策、风控、订单、日志 | 已有实现；本机服务处于 active/running | 连续运行、故障恢复、成交核对记录 |
| 规则与 LLM 配对评分 | 有实际输出 | 不重叠样本、置信区间、不同市场状态和账户口径比较 |
| 策略提出与生命周期 | 有实现和历史运行记录 | 候选确实被服务、产生成交、改善样本外表现 |
| 波动率风险判断 | 已有实现与历史研究；VIX 扩展未提交 | 当前预测与所评级预测一致，数据新鲜且可复现 |
| 持续盈利 / 60 日超额收益 | 未验证 | 完整 60 交易日窗口、成本、收益曲线、风险暴露、统计不确定性 |
| 新贡献者安装与 CI | 入口迁移存在实测故障 | 无凭证新克隆跑完整文档流程 |
| 网页、结构化只读 API、设计系统 | 尚无前端文件 | 第一版真实数据只读面板 |

不以“完成 80%”描述此项目：工程链路、策略有效性、开放贡献体验、产品界面是四个不同维度。

## 3. 当前结果的正确解释

本轮 `make benchmark` 输出：19 个交易日、1745 个周期；运行期间 daemon 继续写入，归因段读取到 1746 个决策。因此这是一份运行中的观察，不是冻结数据集的实验。

- 六个策略中五个落后同资金、各自同时间区间的 SPY；唯一领先者 `fixed-size-probe-0001` 超额约 +0.68 个百分点。
- 47 个已平仓 lot 的已实现 PnL 为 +757.95；已实现加未实现为 +768.46；按假定 0.05% 往返成本后为 +750.55。这是 paper 记录的结果，不能称为实盘利润。
- LLM 配对记录 45 个、改判 39 个、其中 36 个探针值优于规则；+17.676% 是单股、24h 探针值的累计值，不是资金收益率，也没有证明独立样本下显著为正。
- 975/1746 个决策无法归因到模型，约 56%。既往记录不能靠补写模型名修复。
- 历史误卖的账户所有者 29 股收益 +2821.65 被单列，不在策略 PnL 中。保留这个事故及修复证据；前端也必须分开呈现账户与 agent 的持仓和收益。
- 策略行是 gross 口径，账户段另扣成本；总体 verdict 由“是否有任何策略落后”决定。它与“整体 agent 在统一 60 日窗口内扣成本后跑赢 SPY”不是同一个判决，需要修正定义和结构化输出。

历史研究证据：2026-10-07 trial 快照为 59 次，47 INSUFFICIENT、12 OVERFIT、0 PASS。2026-10-08 模型比较的 18 个可评分模型没有在该 SPY 短样本中证明方向能力；价格/新闻研究也没有找到通过所述检验的可交易方向优势。不能把这些有限实验概括为“市场方向不可预测”或“LLM 永远没有作用”。波动率管理降低回撤但可能降低收益，不能将降低回撤直接说成 alpha。

本轮运行 gate 的最新研究台账为 **70 次，55 INSUFFICIENT、15 OVERFIT、0 PASS**。同一次 gate 中，运行指纹与工作树一致；真实 bars 上的隔离回放跑了 847 个周期，反思→评分→筛选→生命周期链路通过。回放证明链路可运行，不是收益优势证明。

Alpaca 明确说明 paper 不模拟市场冲击、延迟滑点等真实交易因素；未来报告要单列这些局限和成本压力测试。[官方 paper 文档](https://docs.alpaca.markets/us/docs/paper-trading)

行情、VIX、长期日志保留的判断属于静态审查发现，需要最小复现实验确认影响范围；本轮没有通过 broker 故障注入证明漏洞。VIX 项属于原有未提交工作，先与该工作单元协调后再实施。

不要为了“更现代”换 broker SDK、引入消息队列、重写为微服务、加多 agent 投票或自动代码生成。现有单进程/单日志结构足够支持下一阶段；先修实际阻断和重复计算。

## 5. 名字、定位与迁移

**建议保留 Autopoiesis 作为当前正式名称，完成一次迁移，不再立即改第二次。** Git remote、Python 包、项目 metadata、README、CLI 已经采用该名；当前故障来自迁移不完整。QuantGroup 可作为组织/团队名，min-agent 仅作为历史标识或明确记录的兼容入口。

对外完整写法：`Autopoiesis — Auditable, self-evolving paper trading`。中文：`Autopoiesis：可审计的自演化模拟交易系统`。优势是符合 self-making 使命；不足是难拼、难发音、名字本身没说明交易，副标题补足。

如果以后确实更名，先评价易读易记、项目使命、搜索冲突、GitHub/PyPI/域名可用性，再决定。可讨论 `ProofTrade` / `EvoLedger` / `TradeLoop` 等方向；它们只是候选，**没有核验可用性或名称权利**。不要先注册/批量替换再调查。

迁移清单：仓库与 remote、package/CLI、service/timer、配置位置、runtime 路径、README/CI/模板、链接与示例。环境变量 `MIN_AGENT_*` 是否迁移是单独设计项；先保留稳定配置，若引入新变量需明示优先级、冲突拒绝、弃用版本。数据迁移先备份、dry-run、计数核对；不改写历史 journal、历史 commit 或逐字证据。

## 6. 网页前端：先能看懂，再能操作

网站有两个用途，分开交付：公开项目站解释项目、安装、架构、证据和贡献；本地操作面板观察一个 paper 实例。公共网站不暴露本机账户、持仓、日志或凭证。

### 第一版页面

| 页面 | 必须回答的问题 | 关键内容 |
|---|---|---|
| Overview | 当前能否信任系统正常运行？ | paper 标记、运行状态、最近周期、行情年龄、Guardian 状态、19/60 覆盖、告警 |
| Decisions | 这次为什么做/不做？ | 规则决定、LLM 改判与理由、数据来源、Guardian 理由、订单与成交状态 |
| Portfolio & Risk | agent 承担了多少风险？ | agent/账户所有者持仓分开、总暴露、剩余额度、成本、亏损阈值 |
| Strategies | 自演化究竟改变了什么？ | 生命周期时间线、服务周期数、真实成交数、评分、退役原因与证据 |
| Evidence | 结果是否经得住核对？ | 同窗口基准曲线、成本口径、样本/独立样本、置信区间、试验全集、导出 |
| System | 谁在运行，哪里失效？ | commit/运行指纹、只读脱敏配置、broker/LLM/数据健康、版本与刷新时间 |

公共站第一版只需要：首页、Quick start、Architecture、Evidence、Contributing。真实收益图只有在可公开的真实数据与口径经过核对后出现；无数据就显示无记录，不展示虚构盈利曲线。

### 最小技术设计

1. 先把已有 evaluator/doctor 的结果变成共享的类型化报告。内部计算一次，CLI 和页面复用；不要让 JavaScript 从散文或原始 journal 重新算收益。
2. 第一阶段用 Python 生成 `report.json` 和静态 HTML/CSS/少量原生 JavaScript，以原子方式发布快照。复用现有报告定时任务，不让网页请求扫描整份 journal。不需要 Node 工具链；所有新依赖仍放 pyproject，所有入口放 Makefile。
3. 输出生成时间、源数据区间、来源、缺失原因、schema_version、commit。页面显示 STALE/UNKNOWN/EMPTY/ERROR，关闭页面时报告生成与交易照常运行。
4. 确需持续查询时再引入独立的只读 HTTP 服务，默认绑定 127.0.0.1，仅访问脱敏快照，不初始化 broker executor。服务依赖放 `web` 可选项；公共部署使用单独发布的数据。
5. 候选接口合同：`/api/v1/overview`、`/decisions?cursor=`、`/strategies`、`/portfolio`、`/evidence`、`/health`。时间戳采用 UTC，界面可选交易所时区；分页和缓存避免全量日志传输。
6. 等多个读页面确实跑通，才讨论暂停/恢复等写操作；后者需要认证、审计、明确权限和仍然经过现有控制路径。本阶段没有网页交易按钮。

若后续选择 React/Vite，必须先明确 AGENTS.md“依赖只在 pyproject 声明”与 Node package manifest 的冲突；不能静默新增第二套依赖管理。当前轻量静态方案足够完成第一版，不要求修改这条约束。

### 视觉方向与验收

风格是研究仪表与证据台：石墨色底、暖白文字、青绿状态强调、琥珀色不确定、红色失败；每种状态同时带文字，不能只靠颜色。标题用有辨识度的衬线字体，正文用清晰中文字体，数字用等宽字体；自托管并记录字体许可，避免浏览器外链字体请求。

主视觉不是“AI 会赚钱”，而是 `Observe → Decide → Guard → Execute → Evaluate → Evolve` 的可展开证据链。第一页先显示运行状态和证据覆盖，收益卡旁边始终附时间区间、成本和基准。

桌面可侧栏+高密度表格；手机按重要性堆叠。图表时间区间、资金基准和成本统一；null 显示未知而非 0。键盘导航、可见焦点、正常字号、文字对比度至少 4.5:1、reduced-motion、空/错误/过期状态都进入验收。支持导出报告和分享某条脱敏决策证据。

可验收目标：导出指标与 CLI 完全一致；刷新或浏览不产生订单、不修改交易配置；无凭证演示正确显示空状态；从概览到任意拒单/退役原因可在三次点击内到达；用真实规模快照实测首屏与响应耗时后再设性能目标。

## 7. 开源项目还缺什么

- **先修可贡献入口**：make check、离线示例、测试分类与 CI 必须对新贡献者一致。提供无 broker 的真实可运行 Guardian 示例，以及明确标注的测试 fixture；fixture 不进入 paper 账本。
- **当前状态与路线图**：保留 STATUS 历史，不用 3472 行流水账承担入口。新增短状态页与本路线图的入口，列支持能力、证据范围、已知缺陷和优先 issue。
- **贡献任务**：将 P0/P1 拆成单问题 issue，写基线、修改范围、验收命令和证据；维护 `good first issue`、`help wanted`、research 标签。收益差与数据/代码 bug 分开。
- **社区与治理**：已有 Apache-2.0、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、bug 模板、PR 模板；补维护者职责、发布规则、研究提案模板和支持方式。现有行为准则需要明确可用的私下联系渠道；只有维护者能真实兑现时才保留安全报告响应时限。[GitHub 社区资料说明](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/about-community-profiles-for-public-repositories)
- **发布**：先做受检验的 alpha release/tag、changelog、兼容边界与安装说明；默认只支持已验证的 Python/操作系统组合。再增加最低/最新支持版本矩阵、构建 wheel/sdist、安装已构建包的验证。PyPI 发布另作明确发布任务。
- **资料与隐私**：研究数据给下载说明、来源和 hash；原始市场/新闻数据的再分发权需按提供方条件核实。公开 evidence 经过账户信息和凭证检查，保留全部失败试验。当前未扫描全部历史凭证，不能宣称完整历史安全审计已通过。
- **README**：先解释用途、当前结果与局限，再给复制可跑的安装路径；增加一张真实只读面板截图、架构图和贡献入口。英文为主要开源入口，提供中文快速开始，减少两套重复文档的漂移。

## 8. 研究下一步怎么做

优先路线是**风险判断可靠性 + 可执行、可证伪的研究管线**。停止无假设的模型轮换与更多投票组合；现有比较没有证明继续扩大模型数量有价值。

每轮只测一个问题：在给定数据、成本、窗口、样本功效下，什么预测能比指定基线带来什么增益？先登记假设、筛选/测试日期、参数预算、最低独立样本、统计检验和停止条件；冻结测试集并登记所有试验，避免重复查看同一“样本外”集后继续调参。

推荐顺序：

1. 复现现有 EWMA 风险结果，查实际预测与质量评分一致性；用相同风险预算比较恒定暴露、波动率目标和目标风险匹配的基准。报告收益、回撤、Sharpe、交易成本和风险暴露，不把其中一个指标替代主使命。
2. 对 VIX 下限单独做样本外及不同市场状态测试，记录过期/不可用率。研究数据不能通过一个不受管理的 runtime cache 静默决定生产行为。
3. 新闻/财报文本用于抽取、事件解释、风险识别；评估事实准确率、时间可知性和具体决策增益。避免仅用收盘已反映的新闻解释收益后再宣称可交易。
4. 基本面先建立 point-in-time 合同：报告期末、发布时间、抓取时间、修订版本分别保存；当前抓取的历史信息不能冒充历史时点已知数据。SEC 有 filings/XBRL JSON 接口，可作为正式披露来源；数据缺失保留缺失。[SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)
5. 有通过离线筛选的候选，先 shadow，再 bounded paper probation；依次核对服务、真实成交、样本数、成本、风险与效果。没有 PASS 就记录失败并停止该假设，不强制产出一个“能交易”的策略。

LLM 的归因分两层：单动作探针衡量局部决策；完整规则组合与 LLM 组合在独立账本、同起始资本/限制/成本下比较整体策略路径。后一层是明确标注的离线模拟或独立 paper 实验，不能把反事实订单写成券商确认成交。

## 9. 分阶段执行与验收

下面工期是假设一名熟悉代码的维护者的工作量估计，不是交付承诺。研究观察时间由市场与样本决定，不由开发日历决定。

| 阶段 | 预计工作量 | 工作包 | 完成条件 |
|---|---|---|---|
| A：恢复贡献闭环 | 1–3 工作日 | 修包/服务/路径迁移；使 CI、新克隆验证实际 make 入口 | 干净 clone 安装、check、离线 smoke、self-test、离线 gate 通过；SKIP 明列 |
| B：可信测量 | 3–5 工作日 | 定义总体/策略/窗口/成本合同；共享结构化报告与固定快照 | 同一份数据 CLI/JSON 指标一致；不足 60 日为未验证；坏数据非零 |
| C：数据与风险 | 3–5 工作日 | 行情时间、VIX 数据合同、研究 extra/Makefile、长期证据保留设计 | 三种过期/缺失/未来数据情形可复现；一个真实研究完整复跑；归档恢复验收明确 |
| D：只读面板 | 5–8 工作日 | 静态快照、Overview/Decisions/Strategies/Evidence、响应式设计 | 真实数据完整链路；空/过期/故障状态；页面无交易能力 |
| E：开源 alpha | 2–4 工作日 | 当前状态、社区、安装支持、公开站、截图、alpha release 候选 | 外部贡献者按文档独立跑通；站点不含私有运行数据 |
| F：有效性观察 | 持续，至少补足 60 交易日及所需统计功效 | 日报、风险匹配基准、LLM 消融、候选策略 | 连续可追溯记录；目标过关或明确失败；结果不足也如实记录 |

正常可按约 4–6 周完成工程和面板 alpha；60 个交易日约 12 个交易周，当前分散记录的 19 日不等于还有 41 个自然日。连续数据、窗口合同、统计功效未满足时继续标为未验证。实盘不在本计划范围内。

## 10. 建议提交顺序

1. 恢复当前包名下的 check/CI/offline smoke；同时说明预期缺凭证的退出状态。
2. 对齐 service 和 runtime 入口，给出迁移验证。
3. 新克隆执行真实用户路径并重新生成日志。证据日志指向真实被测提交，不手工“更新”编号或路径。
4. 固定 benchmark 合同和结构化报告。
5. 行情/VIX 时点与可复现研究环境；其中 VIX 独立于行情修复提交。
6. 共享只读快照与第一版页面；网页设计与交易模型不混在一个提交。
7. 更新当前文档、公共站与 alpha 发布候选。

每个提交先写具体基线和成功标准，再修改，运行相关最小检查；合并前跑完整 check 与需要的 gate。自检会临时创建故障 canary，必须与 test/gate **顺序执行或放独立 checkout**。运行 gate 不代表要为使它变绿而降低风控或修改交易结果。
