### 1. 阶段 B：可信测量 — commit `fc6e35f`

计划指出的定义错配实测存在，而且是两个缺陷：

**(a) 判决是错的声明。** 退出码契约写"至少一个策略落后即失败"，于是一个弱策略失败就让整个
agent 读作失败——项目对外引用的"6/6 落后、最差 2.94 点"就是这个数。目标句说的是 agent：一个
资本基、扣成本、一个窗口。两者现在都算、都打印、都标注，退出码跟目标句：

    VERDICT FAIL: the agent returned +1.95% on deployed capital after cost against SPY +2.80%
                  over the same window (-0.85). 6 of 6 strategies are behind buy-and-hold on their
                  own capital and window (worst tiny-fixed-size-001 by 2.94 points)
                  - a diagnostic, not the target

agent 落后 0.85 点，不是 2.94。**更小的失败，但仍是失败**——旧数字错在让项目看起来比自己的记录
更差，而错因是声明定义而非严格。

**(b) 市场腿变成了另一个总体。** `_market_return_pct` 取记录里首尾两个报价相除。universe 放宽
到 tradable 后一轮覆盖最多 15 个标的，该序列从 SPY 739.24 跑到一只 $6 股票的 11.31，于是报告
"交易标的回报 -98.47%"——而同一窗口 SPY 是 +5.41%。比较腿悄悄变成了与被判 PnL 不同的总体，
正是该函数 docstring 自己警告的失败，只是从"第二个数据源"改从"总体"进来。已限定为 lot 实际
交易的标的。

这个缺陷是**建 agent 级 block 时发现的，不是读出来的**：第一版无法从 doctor 散文里恢复资本腿，
于是直接调 evaluator，而它第一个产出的就是 -98.47%。同一路径又揪出两个并已修：未播种 journal
fills 导致 `closed_lots` 为空、把未平仓的 +24.19 当成 agent 全部记录（真实 +867.73）；以及把往返
成本计到未实现腿上，低估了仓位。

### 3. VIX 下限同口径 A/B — 结论：是风险措施，不是 Sharpe 改进

同 bars、同成本、同窗口、同目标波动率，下限开关两臂：

    sym   CAGR              Sharpe            max drawdown      engaged
    SPY   8.33 -> 6.71      0.756 -> 0.714   -36.87 -> -26.52   43.1%
    TLT   2.93 -> 3.49      0.314 -> 0.394   -39.85 -> -30.25   36.1%
    XLE   5.02 -> 3.99      0.456 -> 0.420   -47.26 -> -44.42   44.2%
    XLF   4.70 -> 3.35      0.436 -> 0.369   -35.75 -> -36.28   45.8%

回撤更浅 3/4，Sharpe 更高 1/4，收益更低 3/4。**它做的是波动率目标做的事：用收益换取撤。**
SPY 上是 1.62 个 CAGR 点换 10.4 个最大回撤点，而 Sharpe 略差。它是风险措施，现在也这样记录——
不是边，这是它唯一被制造时的声称。

**测量本身的两个静默缺陷，都是跑出来才发现的：**
1. 每个历史日都拿**今天**的 VIX 判。`vix_floor` 读缓存最后一点——对实时路径是对的，对任何回放是
   错的。于是下限在 99.9% 的日子生效，那正是回填的签名，而它看起来酷似一个替换了预测的下限。
2. 生效率计数用 `"engaged" in note`，而 "floor **not** engaged" 也含它——一个从未触发的下限报告
   100% 生效，同时两臂数字完全相同。输出里这个自相矛盾是看得见的，是子串 bug 造出来的。

`make research-vix-ab` 可复跑。
