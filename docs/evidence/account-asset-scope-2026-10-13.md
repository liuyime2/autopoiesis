# 全账户与资产支持范围审查

审查日期：2026-10-13。用户明确要求范围包括期权、加密货币等资产。
本文区分资产可见性、券商账户权限、策略覆盖及可验证的交易能力；仅有
账户 ACTIVE 或股票下单入口，不足以证明多资产控制。真实账户权限清点待运行，
以下实现范围来自当前代码及只读离线审查。

| 资产或操作 | 当前项目能力 | 尚未完成的验收 |
| --- | --- | --- |
| 美股与美国交易所上市 ETF | 股票行情、策略选择、Guardian、paper market/day 订单和成交账本 | 只有冻结策略实际覆盖的标的才能形成合格交易；开盘后的新周期仍待观察 |
| 债券、商品、加密主题及杠杆/反向 ETF | 如券商分类为 us_equity，走股票路径；描述中可体现其测量风险 | 不代表能交易 ETF 的底层债券、期货或数字货币；独立产品风险验收尚无证据 |
| 账户原有股票持仓 | manage_account=true、universe=tradable 使其进入账户管理范围和整账户敞口检查 | 无合格策略时 HOLD；授权范围不能代替逐标的策略覆盖 |
| 股票做空与回补 | 存在 SHORT/COVER 和归属计算 | 当前 shorts=shadow，保持影子执行；外部来源 short 的整账户回补尚未实现 |
| 分数股 | 持仓读取为浮点数量 | 决策订单为整数，不能声称能完全清除小于一股的残余 |
| 期权 | 券商有独立期权接口；现项目缺专用交易适配 | 合约元数据/乘数、期权行情、权限、风险、到期/行权/指派及费用归属 |
| 加密货币 | 券商有 crypto 交易接口；现项目缺专用交易适配 | 交易对行情、24/7 时钟、数量精度、费用、订单类型及成交核算 |
| 现金、购买力、挂单 | 可从券商只读获取，与整账户持仓共同核对 | 不完整或非有限数值必须拒绝；完整清点结果须绑定真实执行时刻 |
| 其他市场或资产 | 未实现并未验收 | 先证明券商接口、账户权限及资产模型支持，不能由 symbol 字符串推断 |

券商的[期权官方文档](https://docs.alpaca.markets/us/docs/options-trading)
说明账户有 approved/trading levels，期权需要独立合约信息，并存在到期、行权和
指派事件；[crypto 官方文档](https://docs.alpaca.markets/us/docs/crypto-trading)
说明其交易时段为全天全周并有适用地区限制。paper 环境也模拟 crypto，见
[paper 官方文档](https://docs.alpaca.markets/us/docs/paper-trading)。这些说明券商
提供能力，不证明当前账户权限或本项目已经正确使用这些能力。

只读审查基线为 68 项相关测试通过。随后账户边界单元的模拟 RED 实测
17 failed / 25 deselected：包含 SDK 默认 50 条导致漏读挂单，以及未知、crypto、
options 资产进入股票报价路径。模拟结果用于证明软件缺陷，不能冒充真实账户
包含这些资产或已有真实下单失败。修复、独立复审和真实清点结果随后补录。

下一步按以下验收顺序推进，不能通过扩大 allowlist 或放松 Guardian 跳过：

1. 全账户只读清点及数据/挂单完整性；未知与未实现资产明确拒绝股票执行。
2. 当前股票/ETF 新源码部署，真实数据→决策→Guardian→paper→成交反馈，
   核对账户中的每个持仓及其策略覆盖，缺覆盖项明确列出。
3. 修复最近账户快照用于 curriculum 的过期持仓问题；设计分数股与授权回补，
   保留影子限制，分别证明不会超卖或误动未授权持仓。
4. crypto：专用只读行情和资产模型→独立时钟/精度/费用/风险→离线拒绝与
   会计测试→影子观察→审计过的有限 paper。
5. 期权：合约和权限清点→乘数与组合最大损失/到期风险→行情和生命周期
   账本→离线验证→影子观察→审计过的有限 paper。
6. 每类资产分别验证研究成本、冻结策略和样本外决策，之后才讨论扩大资本。
   当前没有新的有效 alpha、受控 RSI 优势或长期真实盈利证据。

开盘准备继续以 2026-10-13 最近一次美股 paper 开盘为目标。多资产范围审查
不能被写成多资产交易已完成，未验收的资产不会自动启用交易。
