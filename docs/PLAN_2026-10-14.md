## 2. 不可变约束

## 3. 工作包（按执行顺序）

每个包都按 基线 → 方案 → 小改 → 测试 → gate → 记录 执行；“验收”必须是命令输出或下一交易日的实盘记录。

### P0 部署纪律（今天收盘后，最先做）

- 指定唯一部署者（Codex 或 Claude），另一方只在自己的分支工作。
- 部署工作树的未提交改动：提交（带测试）或回退，二选一。
- 部署前检查清单：`git status` 干净、CI 三版本绿、`make verify` 52/52、医生检查 0 失败；部署后核对守护进程代码指纹等于工作树指纹。
- 验收：部署记录写入 `docs/evidence/`，包含提交号、CI 运行号、指纹。

### P1 停止机械卖出（D1，今天收盘后）

1. 增加经审计的操作员入口 `pause-strategy <id> --reason`：写 journal 事件、更新生命周期、医生检查的生命周期来源项能追溯到它。
2. 用它暂停 `fixed-size-tlt-sell-001`、`fixed-size-xle-sell-001`、`fixed-size-xlf-sell-001`。
3. 准入门：拒绝没有市场条件的 `SELL` 试探作用于非本代理建立的仓位；任何试探策略必须有累计上限（例如最多 1 次成交）后自动结束。
4. 课程模块：不再把“持仓没有退出策略”当作需要填补的缺口。
- 验收：单测覆盖 2、3、4；下一交易日 TLT/BIL 卖出 0 股；医生检查生命周期来源 OK。
- 停手条件：若暂停入口无法写出可追溯的生命周期记录，不得用手改文件代替。

### P2 修复模型输出截断（D3，今天收盘后测量，明天收盘后部署）

1. 复现：取 10-12/13 失败周期的真实上下文，记录提示词 token、思考 token、`done_reason`。
2. 按测量值设置 `DECISION_NUM_CTX`（参照课程模块的做法），并实测耗时不超过决策超时。
3. 回退下单的处理：回退时只允许 HOLD 或减仓，禁止回退规则新开仓（需单独测试和记录理由）。
- 验收：下一交易日解析失败率 < 2%；回退比例写入日报。

### P3 自主关注与未覆盖标的的决策（D2）

1. 未覆盖标的：以 HOLD 为基线让模型决策，可带理由推翻；这类决策标记为 `no_strategy`，不计入任何策略的评分和生命周期。
2. 关注名单由模型选择：从券商活跃榜/涨跌榜（经现有质量过滤）给模型候选和数据，模型选出 N 个并写理由；选择本身记录，并在 24 小时后评估“被选中的标的是否比未选中的更有信息”。
3. 课程模块可为被关注且反复出现的标的提议有条件的策略（RULE DSL），走正常准入。
- 验收：关注标的有带理由的决策；Guardian 照常拦截；策略评分中 `no_strategy` 决策为 0。

### P4 度量修正（D4、D5）

- `llm vs rule`：排除系统跳过和无理由的推翻；覆盖全部交易标的；输出按天分布；少于 20 个交易日时只报告“证据不足”，不报告净值结论。
- 医生检查的决策质量改为全部标的。
- 修复日报重复行。
- 验收：对 10-07 至今重算并写入证据文件；日报只显示一行 `pnl attribution`。

### P5 CI 与合并（D6）

### P6 风险判断增强：期权隐含波动率

- 基线：IV 中 EWMA 解释不了的部分，对未来 21 天波动率的预测在检验期 ρ=+0.60（p=0.0003），但只有 52 天；130/314 个采样日有可用 IV。
- 方案：逐日采样（2024-02 至今），放宽到按成交量最大的近平值合约，补足样本；按信号门（时间切分、按月分块、账本计数）重新检验。
- 若通过：先以 shadow 方式把 IV 写入风险块（只记录、不影响建议），20 个交易日后比较预测误差，再决定是否启用。
- 停手条件：通过的证据只来自单一窗口时，不启用。
